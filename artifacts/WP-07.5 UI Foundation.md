# WP-07.5 — UI Foundation

WP-07.5 is an implementation-sequence addendum inserted after WP-07 and before WP-08. It does not rewrite the frozen Engineering Implementation Specification or change scientific architecture.

## Design principles

The interface is calm, structured, trustworthy, educational, exploratory, accessible, and restrained. Hierarchy comes from spacing, typography, surface contrast, borders, and semantic labels. It avoids marketing gradients, glass effects, glow, hover scaling, oversized hero treatment, diagnostic-dashboard language, and decorative motion.

## Ownership

- `app/app.config.ts` selects Nuxt UI's generic primary and neutral palettes.
- `app/assets/main.css` owns application tokens, global typography, generic surfaces, focus, spacing, elevation, and motion foundations.
- `app/components/ui/` owns only stable product semantics: page header, panel, safety notice, and evidence badge.
- feature components compose those semantics and use Nuxt UI primitives directly for ordinary buttons, cards, badges, alerts, containers, and tooltips.
- `visualization/system-map/`, LayoutArtifact data, GraphNode shapes, SVG edges, Clinical Anchor separation, and spatial keyboard behavior remain custom and independent of Nuxt UI.

## Tokens and hierarchy

Generic tokens cover the page background, three surface levels, borders, text hierarchy, a teal interactive accent, amber focus, radii, a compact spacing rhythm, restrained elevation, interactive timing, and system-font stacks. Scientific category colors and relationship line meanings remain in System Map visual-semantic ownership rather than the generic application theme.

Surface levels are limited to page background, primary workspace, secondary information, quiet control grouping, and safety/evidence callouts. Avoid nesting decorative cards when spacing or a separator is enough.

## Typography

The hierarchy distinguishes page title, section title, panel heading, body, supporting text, metadata, canonical IDs, and safety/evidence text. English uses a resilient system sans stack. Persian uses a deliberate system stack led by Tahoma and Segoe UI, avoiding a new network or font-asset dependency. Canonical IDs remain isolated LTR and use the mono stack.

## Primitive policy

Use Nuxt UI for generic primitives when it improves consistency. Do not wrap every Nuxt UI component. Add a shared component only for stable product meaning rather than styling convenience. Native controls remain appropriate where their semantics are stronger or where scientific shape grammar is part of the control, as with System Map layer checkboxes.

## Safety, evidence, RTL, and accessibility

Safety notices receive authoritative strings from `SafetyAccess`; the shared component does not own or rewrite medical copy. Evidence remains a textual qualitative label (`Clinical`, `Strong`, `Moderate`, or `Limited`) and never becomes a score, percentage, meter, or diagnostic strength.

WP-05 continues to own locale routing, `lang`/`dir`, localization lookup, and bidi isolation. WP-07 remains a regression boundary: selected and focused node state stay separate; roving tabindex, spatial arrows, Enter/Space, Escape, focus transfer, semantic synchronization, renderer fallback, visible focus, and reduced motion remain intact.

## Motion

Motion is short and functional. Reduced-motion mode effectively removes transitions without removing meaning. No decorative motion dependency is introduced directly by the application.

## Portfolio reference

Reused ideas: centralized app configuration, semantic variables, direct Nuxt UI primitives, shared page/container patterns, reusable interactive states, and locale-aware typography.

Explicitly not copied: violet personal branding, marketing gradients, glass-card styling, strong hover scaling, portfolio hero/CTA treatments, dark-mode infrastructure, content architecture, font assets, and unrelated dependencies.

## Future feature readiness

The foundation can compose future cards, selectors, context sections, alternative explanations, educational callouts, evidence entry points, and presentation/source surfaces. None of those WP-08+ features are implemented here.
